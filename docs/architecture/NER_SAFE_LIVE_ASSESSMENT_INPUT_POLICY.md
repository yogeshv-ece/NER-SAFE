## 1. EXECUTIVE SUMMARY & TEMPORAL ARCHITECTURE

Landslide hazards in the North Eastern Region of India (Meghalaya, Mizoram, Assam, Sikkim, Arunachal Pradesh, Nagaland, Manipur, Tripura) are driven by a combination of steep, susceptible mountain topography and fast dynamic hydrometeorological triggers.

To balance scientific responsiveness with computational rigor, NER-SAFE organizes environmental signals into three distinct temporal layers:

## 2. MINIMUM QUALIFYING INPUT RULES

### Rule 1: Fast Dynamic Trigger Sufficiency
A genuine new **Fast Observation** (such as a new half-hourly NASA GPM NRT observation or a real ground rain gauge record) is **scientifically and operationally sufficient** to trigger a dynamic operational risk reassessment across all 48 regional hotspots without waiting for a new 5-day optical satellite pass.

* **Rationale**: Monsoon convective storms in the Khasi Hills and Aizawl slopes evolve within hours. Waiting for cloud-free optical imagery during monsoon downpours would paralyze early warnings when hazards are highest.

### Rule 2: Companion Input Concurrence
When a new Fast observation arrives:
1. The **Rainfall Anomaly** ($r_{\text{anom}}$) component is recalculated dynamically from the newly acquired precipitation array.
2. The **Soil Moisture Anomaly** ($s_{\text{anom}}$) uses the latest valid contextual SMAP radiometer observation or authenticated ground tensiometer readings.
3. The **Satellite Surface Change** ($c_{\text{sat}}$) uses the latest cloud-screened optical pass or all-weather Sentinel-1 radar backscatter alteration.
4. The **Susceptibility Baseline** ($s_{\text{base}}$) remains the locked 30m geomorphic susceptibility probability generated by the calibrated Component 10 Random Forest model.

### Rule 3: Four-Factor Weighted Fusion Formula
Every live operational assessment strictly executes the locked four-factor fusion equation:

$$\text{Risk\_Score} = 0.40 \cdot \text{Susceptibility} + 0.30 \cdot \text{Rainfall\_Anomaly} + 0.20 \cdot \text{Soil\_Moisture\_Anomaly} + 0.10 \cdot \text{Satellite\_Change\_Flag}$$

* **Weight Invariance**: The weights $0.40 / 0.30 / 0.20 / 0.10$ are immutable. They cannot be altered for individual assessments.
* **Tier Cutoffs**:
  * $\text{Risk} \ge 0.65$: **CRITICAL** (Red — Immediate field inspection / evacuation warning)
  * $0.48 \le \text{Risk} < 0.65$: **HIGH** (Orange — Priority corridor inspection / traffic advisory)
  * $0.32 \le \text{Risk} < 0.48$: **MODERATE** (Amber — Weather evolution watch)
  * $\text{Risk} < 0.32$: **WATCH** (Green — Baseline environmental monitoring)

## 3. ZERO-TOLERANCE RULES & SCIENTIFIC SAFEGUARDS

### Rule 4: Zero Recycling of Stale Risk
* When no new qualifying observation has arrived since the last assessment, the system **MUST NOT** generate a fake new assessment simply because the user refreshed their browser or the scheduler polled the source.
* Re-polling an already current observation yields `ALREADY_CURRENT` and suppresses duplicate reassessment.
* If all fresh data feeds expire beyond product latency cutoffs:
  $$\text{Current Operational Risk} \rightarrow \textbf{CURRENT RISK: NOT AVAILABLE}$$
* Previous assessments are preserved as historical reference and labeled:
  $$\textbf{HISTORICAL ASSESSMENT — NOT CURRENT OPERATIONAL RISK}$$

### Rule 5: Missing Observations Never Mean Safe
* If a satellite pass is cloud-occluded, if an external API is down (`SOURCE_UNAVAILABLE`), or if credentials are unconfigured (`AUTH_REQUIRED`), the system **NEVER** assumes zero risk.
* Data gaps are displayed with distinct operational flags: `SOURCE_UNAVAILABLE`, `AUTH_REQUIRED`, or `AWAITING_INSTITUTIONAL_MOU`.

### Rule 6: Absolute Isolation of Demo / Replay
* Operational live monitoring and judge demonstration replay are governed by two distinct execution branches:
  * **Operational Mode**: Uses live observation IDs (`GPM_3IMERGHHE...`), real acquisition timestamps, dynamic risk calculations, and persistent `ASM-LIVE-...` records.
  * **Demo / Replay Mode**: Uses pre-staged local demonstration datasets (`EVT-MEG-001`, `0.7055`, `CRITICAL`), fixed historical timestamps (`2024-05-28T06:00:00Z`), and is visibly labeled `MODE: DEMO / REPLAY`.
* Demo data can never leak into the operational SQLite database or live dashboard card.
